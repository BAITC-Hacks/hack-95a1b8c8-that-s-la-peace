# Интерфейс подбора подрядчиков

Часть Ilyas для кейса #79-lite. Форма принимает город, дату, формат, категорию,
бюджет и необязательные язык/длительность. Показывает до трёх карточек в порядке
backend, объяснения, цену «от», признаки данных и разные причины пустой выдачи.
Есть проверка полей, загрузка, ошибки и повтор; при изменении параметров старая
выдача убирается. Все данные API выводятся как текст.
Общая подпись раскрывает демонстрационный каталог и изменённые имена.
Если подходящих больше трёх, UI объясняет действующий порядок: совпадения
описания с форматом, затем категорией, затем меньшая начальная цена.

Подбор, фильтрация, ранжирование и объяснения выполняются backend Dinmukhammed.
В опубликованном backend a0918c8 это локальный детерминированный алгоритм,
без LLM и внешних API. Codex применяется при разработке. В frontend нет
встроенных рекомендательных карточек или успешных тестовых ответов. Есть
отдельная справка агрегатов исходного каталога, описанная ниже. Проверка интерфейса
на fixtures не означает готовность всей системы.

## UX-пакет по запросу Ilyas от 23.09.2026

- Город, формат, услуга и рабочий язык выбираются в одном поле с поиском.
  Нажатие открывает список, ввод сужает его; стрелка открывает полный список
  без необходимости печатать. Строка поиска не подменяет подтверждённый выбор.
- Одно поле «Какая услуга нужна»: ведение и шоу, фото и видео, музыка,
  площадки, оформление и подарки. Все 17 исходных категорий сохранены.
  Подписи «Фотосъёмка», «Живая музыка» и другие описывают услугу; API получает
  прежние значения «Фотограф», «Лайв-бэнд» и остальные канонические категории.
- RU / KK / EN переводят интерфейс и подписи справочников, не значения JSON.
  Оригинальные описания, серверные сообщения и объяснения остаются русскими;
  это явно отмечено. Сохраняется только предпочтение языка в localStorage.
- Одно поле даты: ввод ДД.ММ.ГГГГ / YYYY-MM-DD или кнопка календаря в нём.
  На цифровой клавиатуре также можно набрать 15102026: получится 15.10.2026.
  Открывается один месяц с переходами в пределах данных. Бюджет
  отображается с пробелами разрядов; 1.000.000 также преобразуется в 1 000 000.
  API получает integer; дробный, небезопасный или невалидный ввод отклоняется.
- Автоподбор через 650 мс после последнего изменения валидной полной формы.
  Можно отключить и пользоваться кнопкой. Во время запроса форма редактируема,
  запоздалый ответ игнорируется; советы применяются только отдельным нажатием.
- Пастельные поверхности, системный шрифт, основной текст/ввод 16 px,
  короткие переходы с отключением при prefers-reduced-motion.
- Настройки автоподбора/совместимости и подробности алгоритма свёрнуты.
  Причины пустой выдачи, объяснения карточек и оговорки цен остаются доступны.

### Цены, количества, совместимость и календарь

`catalog-guide.json` — производные агрегаты выданного CSV: SHA-256 исходного
файла, числа уникальных профилей по городам, группы город/категория/формат,
начальные цены и число свободных профилей на каждой из 100 дат. В нём нет
id, имён, описаний, контактов или сведений о реальных мероприятиях. Группы
нельзя складывать как уникальных подрядчиков. Цена не является рыночной
оценкой или окончательной сметой; включены исходные синтетические профили
и значения, заполненные при подготовке организаторского каталога.

Справка учитывает город, категорию, формат и выбранную дату; бюджет, язык
и часы в ней не учитываются, что подписано возле чисел. Поэтому D1 имеет
9 профилей по первым трём условиям, 7 свободны на дату, а API при бюджете
1 000 000 возвращает 6 подходящих и до 3 карточек. Это разные множества.
Подбор, ранжирование и объяснения по-прежнему выполняет только сервер.

Списки совместимых категорий/форматов сужаются по тем же агрегатам; текущий
выбор сохраняется. Снятие отметки возвращает все варианты и позволяет явно
проверить исход «в этом городе такой категории нет». Все даты остаются
выбираемыми внутри объявленного окна: ноль в календаре означает отсутствие свободных профилей данной
группы, а не запрет запрашивать дату. Ссылок на мероприятия в данных нет.

Перед показом справки проверяются dataset_version, окно дат и структура.
При несовпадении SHA, повреждении или недоступности файла справка/адаптивные
списки скрываются; обычный календарь и настоящий подбор остаются доступными. Это не fallback с
заранее рассчитанными рекомендациями.

## Запуск своей части — команды

Проверено: Windows, Node.js 24.19.0, Microsoft Edge 153.0.4234.48.
Внешних JavaScript-пакетов и шага сборки для приложения нет. GPU, БД, ключи,
учётная запись или подписка для самого frontend не нужны. Браузер должен
поддерживать JavaScript-модули, fetch, AbortController и Intl.

Из корня репозитория:

```powershell
node frontend/serve.mjs
```

Открыть `http://127.0.0.1:4173`. Без настроенного backend ожидается честное
сообщение «Сервис подбора пока недоступен»; это проверка запуска frontend,
а не рабочего подбора. Остановка — Ctrl+C в терминале сервера; повторный
запуск той же командой. Локальный сервер слушает только loopback.

Для работы с настоящим backend задать `BACKEND_URL` равным его фактическому
origin (протокол, адрес, порт), предоставленному владельцем backend, и повторно
запустить сервер. Пример настройки в PowerShell, если согласованный backend
действительно слушает порт 8000:

```powershell
$env:BACKEND_URL = 'http://127.0.0.1:8000'
node frontend/serve.mjs
```

Порт 8000 — значение по умолчанию опубликованного backend a0918c8; его README
описывает Python 3.12, установку `requirements.txt` и `python run.py`.
Другой путь: backend раздаёт статические файлы `frontend/`
в корне того же origin и обслуживает `/api/` сам; Node-сервер тогда не нужен.
Этот способ необходимо проверить на объединённой версии после интеграции.

| Переменная | Обязательность | Назначение |
| --- | --- | --- |
| `PORT` | Нет, по умолчанию 4173 | Порт локального frontend-сервера |
| `BACKEND_URL` | Для реального подбора через локальный сервер | Origin API без логина, пароля, пути и query; только HTTP/HTTPS |

`frontend/.env.example` содержит безопасные примеры. Сам сервер `.env`
автоматически не читает. При необходимости скопировать пример в `.env`
и запустить `node --env-file=frontend/.env frontend/serve.mjs` на указанной
версии Node. Рабочий `.env` игнорируется Git. API-ключи провайдера сюда
не добавляются: они принадлежат серверной конфигурации backend.

## Контракт и интеграция

Актуальный API v1 описан в `docs/API_CONTRACT.md` общего пакета `13a3707`.
`app.mjs` соединяет
изолированное представление `view.mjs` с транспортом `api.mjs`.

- `GET /api/meta`: `api_version: 1`, `dataset_version` (SHA-256), `cities`,
  `categories`, `event_types`, `languages`, `dataset_count`, `date_range: {min,max}`.
  Значения и окно дат берутся с сервера.
- `POST /api/recommendations`: `city`, `event_date`, `event_type`, `category`,
  целый положительный `budget_kzt`, `duration_hours` (число/null), `language` (строка/null).
- HTTP 200: `status` (`matched`, `no_category_in_city`, `no_matches`), `message`,
  `cards`, `total_in_city_category`, `eligible_count`, `exclusions` с независимыми
  счётчиками `busy`, `budget`, `event_type`, `language`, `duration`; версии API/набора,
  `suggestions` и `explanation_mode`. Версия набора должна совпадать с meta.
- Карточка: строковые `id`, `name`, `category`, `city`, `explanation`;
  целая `price_from_kzt`; булевы `synthetic`, `city_imputed`, `price_imputed`;
  `languages`, `max_hours`, `description_excerpt`, `source` (provided/team_added).
- HTTP 422: `{error:{code:"invalid_request",message,fields}}`; ошибки полей
  отображаются рядом с вводом. HTTP 503, сеть, таймаут или некорректная структура
  ответа показываются как недоступность сервиса без фиктивных карточек.

Frontend не пересортировывает и не фильтрует кандидатов. Счётчики исключений
не складываются. Формат ответа проверяется; выдача более трёх карточек или
противоречивые количества отклоняются как ошибка контракта.

Факты профиля выводятся с сервера; `max_hours=null` подписан как неприменимое
присутствие по часам. Источник отличает выданные профили от добавленных командой.
Режим объяснений честно различает deterministic/llm/deterministic_fallback.
Советы change_date/increase_budget применяются только отдельной кнопкой.
Проверяются полный запрос, изменение ровно одного разрешённого условия,
допустимая дата и повышение начального бюджета; сами рекомендации и
`eligible_count` остаются ответственностью backend. Браузер не заявляет их
проверку на реальном каталоге.

Браузер использует относительные URL того же origin, без cookies и токенов.
Локальный прокси разрешает только две согласованные операции, не пересылает
Authorization/Cookie/Set-Cookie, не выдаёт `.env` или файлы репозитория,
ограничивает тело запроса 16 KiB. Таймаут прокси — 10 секунд, клиента — 12 секунд.
Это ограничения клиента, а не гарантия скорости подбора.

Пример ввода после подключения API: Алматы; 15.10.2026; корпоратив; Ведущий;
1 000 000 ₸; язык/часы не заданы. По исходному CSV 6 кандидатов подходят,
показываются три карточки с конкретными объяснениями. Этот запрос прошёл
живую проверку совместимости fb54b42 + a0918c8 и позднейшие чистые проверки
1162d459 и dev-zoro 6039476. Остальные примеры — `docs/DEMO.md`.
