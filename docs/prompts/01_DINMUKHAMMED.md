## Что реализовать по порядку

1. Поднять Python 3.12, FastAPI, Uvicorn и зафиксированные совместимые зависимости. Создать понятный `run.py` с необязательным --port (по умолчанию 8000), чтобы candidate проверялся отдельным процессом на свободном порту. Раздавать полученный от друга frontend с того же сервера, регистрируя API раньше static mount. Не открывать через static весь репозиторий.
2. Загрузить CSV один раз, проверить уникальность 66 id, разобрать списки `|`, булевы значения, цены, max_hours и ISO-даты. Версия датасета — SHA-256 содержимого. Неверный датасет вызывает понятную ошибку готовности, не пустую успешную выдачу.
3. Реализовать GET `/api/health`, GET `/api/meta`, POST `/api/recommendations` точно по контракту. Поля/статусы не переименовывать. Справочники сортировать стабильно.
4. Нормализовать запрос и применить все жёсткие фильтры. Для неизвестного enum или неверной даты/числа вернуть контрактный 422; для известной категории без профилей в городе — 200 no_category_in_city; для существующей группы без подходящих — 200 no_matches.
5. Зафиксировать объяснимое детерминированное ранжирование подходящих по полезным совпадениям с форматом и описанием, с документированными правилами и последним ключом id. Цена не должна маскироваться под качество; слово «AI» не заменяет алгоритм. Ответ LLM, случайность, текущий час и исходный порядок CSV не управляют порядком карточек.
6. Сформировать 1–2 предложения на карточку с отличительным подтверждаемым фактом из description и соответствием запросу. Сравнивать начальную цену с бюджетом, не обещая итоговую стоимость заказа. Подготовить languages, max_hours, description_excerpt и provenance для сравнения в UI. Не выдумывать сведения.
7. Вернуть причины нехватки карточек и подсчёты исключений. Один профиль может иметь несколько причин; сумма причин не равна числу исключённых людей. Язык и duration_hours, если не заданы/null, не ограничивают подбор. Пустой max_hours не исключает профиль по часам и не означает бесконечный срок услуги.
8. Когда обязательное работает, реализовать suggestions с проверенной сменой ровно одного параметра. Ближайшая подходящая дата внутри календаря, при равном расстоянии более ранняя. Для бюджета — минимальный подходящий price_from_kzt при сохранении остальных условий, только если он больше исходного бюджета. Результат совета повторно проверяется тем же matcher; рекурсивный поиск советов отключить. Если не найдено — suggestions=[]; не предлагать заведомо пустые варианты.
9. Подготовить реальный запуск и README для эксперта. Базовая функциональность должна работать на выданном наборе без личных платных аккаунтов. Если добавляешь LLM, делай серверную интеграцию с тайм-аутом, кешем и честным резервом; не заявляй её реализованной до реального запроса. Не трать первый checkpoint на внешние сервисы.
10. Поддерживать docs/PROGRESS.md, STATE.md, COMPLIANCE.md и THIRD_PARTY.md по факту. ТЗ и предварительные организационные шаблоны раскрыть как источники. Исходники друга и его тестовые результаты не приписывать себе.

## Проверки твоей части

- У CSV 66 уникальных id, 13 synthetic, корректные списки и 9 max_hours без значения.
- Занятые исключаются; площадки подчиняются той же проверке. Цена ровно бюджету допустима, превышение исключается. Проверить формат, язык и часы.
- Пропущенные optional и null дают одинаковую выдачу. Пустые строки интерфейс должен передать как null; не скрывай ошибочные типы сервера.
- Дата включительно от 2026-09-23 до 2026-12-31. Выход за диапазон, невозможная дата, NaN/Infinity, boolean вместо числа, нулевые/отрицательные суммы отклоняются.
- Повторить запрос и сравнить id/порядок, включая перезапуск процесса и перестановку строк CSV при неизменном содержании профилей. Зафиксировать правило ранжирования.
- Проверить matched, no_category_in_city, no_matches, выдачу 1/2/3, объяснение нехватки, соблюдение схемы ошибок.
- У каждого объяснения есть собственный подтверждённый факт; сравнить объяснения без имён. Проверить отсутствие выдуманной окончательной цены и рейтингов.
- Каждое suggestion меняет одно ограничение и действительно даёт >0 результатов. Без совета исходный запрос не изменяется.
- В интеграции: `/` открывает UI друга, тот вызывает настоящее API и показывает реальный результат. HTTP 200 самого сервера не заменяет этот проход.

Анализ CSV даёт удобные запросы: Алматы/Ведущий/корпоратив/1 000 000 ₸ на 2026-10-15 — 6 допустимых; на 2026-10-16 — 4. Алматы/Флорист/свадьба/1 000 000 ₸ на 2026-10-15 — 2; Астана с теми же остальными параметрами — 0 из-за занятости единственного. Зарубежье/Ведущий — категория отсутствует. Алматы/Ведущий при бюджете 1 ₸ — кандидаты есть, подходящих нет. Это исходные контрольные данные, не уже выполненные тесты приложения. Для смены даты подобрать пару, где после ранжирования меняется видимый top-3.
