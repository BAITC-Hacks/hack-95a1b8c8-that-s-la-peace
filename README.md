# That's La Peace — умный подбор подрядчиков

Кейс HackAlem AI #79-lite, трек 06 «Креативные индустрии», Firebird. Пользователь задаёт город, дату, формат мероприятия, категорию и бюджет и получает до трёх рекомендаций с объяснениями на фактах каталога.

## Команда

| Участник | Ответственность | Фактическая рабочая ветка |
| --- | --- | --- |
| Dinmukhammed | Backend, подбор, объяснения и интеграция | `dev-dinmukhammed` |
| Ilyas | Frontend, дизайн, демо и независимая проверка | `dev-zoro`; переход на `dev-ilyas` ещё не подтверждён |

По актуальному handoff Ilyas является капитаном и отвечает за отдельную подачу формы. Интегратор — Dinmukhammed. GitHub-логины и фактическое авторство коммитов сохраняются. Прежняя `dev-dimalarp` оставлена; новая разработка Dinmukhammed идёт только в `dev-dinmukhammed`. Правила совместной работы — [AGENTS](AGENTS.md), [задачи Dinmukhammed](docs/BACKEND_TASKS.md) и [задачи Ilyas](docs/prompts/02_FRIEND.md).

## Текущая версия

Серверная часть: загрузка 66 выданных профилей, фильтрация, детерминированное ранжирование, карточки с объяснениями, разные причины пустой выдачи и проверенные альтернативы даты/бюджета. Интерфейс из ветки `dev-zoro` подключён в `frontend/`: форма, карточки с фактами, состояния ошибок и пустой выдачи, применение предложений по нажатию. Новый готовый пакет Ilyas также добавляет поиск по справочникам, RU/KK/EN, форматирование ввода и необязательный автоподбор; исходные объяснения остаются на русском с явной подписью. Справочные агрегаты привязаны к SHA каталога и не создают дополнительных профилей. Рабочая ветка backend — `dev-dinmukhammed`. Общая сборка — `integration`, она обновляется после проверки обеих частей. Проверенные версии публикуются в main каждые 45 минут по прямому поручению пользователя; график — [RELEASE_SCHEDULE](docs/RELEASE_SCHEDULE.md).

Объяснения и рекомендации вычисляются локально. Внешняя LLM, API-ключи и оплаченные аккаунты для базовой функции не используются. AI-агент Codex используется при разработке; это не называется LLM внутри приложения. Профили анонимизированы, 13 из 66 синтетические; начальные цены и города с заполненными при подготовке значениями отмечаются флагами.

## Быстрый запуск для эксперта

Требуется Python 3.12 и Git. ОС фактической проверки и результаты указаны в [TEST_REPORT](docs/TEST_REPORT.md). Для первой установки нужен доступ к PyPI; после установки обработка запросов полностью локальная. Доступ к официальному репозиторию выдаёт организатор, личный аккаунт участника не требуется для runtime.

Для новой копии официальной опубликованной версии:

```powershell
git clone --branch main --single-branch https://github.com/BAITC-Hacks/hack-95a1b8c8-that-s-la-peace.git
Set-Location hack-95a1b8c8-that-s-la-peace
git rev-parse HEAD
```

Последняя команда показывает проверяемый commit: сохраните его вместе с результатом запуска. Для повторения конкретного отчёта используйте указанный в нём SHA; имя ветки само по себе может двигаться. Все дальнейшие команды выполняются из корня полученной копии репозитория.

Windows PowerShell, установленный Python 3.12; активация окружения и изменение ExecutionPolicy не нужны:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Если команда `py` отсутствует, используйте установленный Python 3.12 по полному пути: `& 'C:\путь\к\Python312\python.exe' -m venv .venv`. Это шаблон пути, замените его реальным путём к своему Python. Версию можно посмотреть через тот же исполняемый файл с `--version`; дальнейшие команды через `.venv\Scripts\python.exe` совпадают. В проверке второго участника использовался именно полный путь к Python 3.12.14; на машине Dinmukhammed проверен launcher `py -3.12` с Python 3.12.10.

После строки Uvicorn о запуске адрес сервера: http://127.0.0.1:8000. `GET /api/health` должен вернуть status=ok и dataset_count=66. Этот же адрес открывает интерфейс. Для приложения достаточно одного процесса Python: Node.js и сборка frontend не нужны. Интерактивная служебная документация API — `/docs`, машинная схема — `/openapi.json`. Документация `/docs` загружает библиотеку Swagger из CDN; основной API и интерфейс этого не требуют.

Остановка — Ctrl+C в терминале сервера. Повторный запуск той же командой не меняет датасет и не требует миграций. Если порт занят, не завершайте чужой процесс: используйте `run.py --port 8002`, затем тот же порт в адресе и smoke-команде. По умолчанию сервер слушает только loopback; `--host` меняйте лишь при осознанной настройке доступа.

## Проверка основного сценария через API

Во втором PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/smoke.py
```

Скрипт выполняет реальные HTTP-запросы к уже работающему серверу: плотная категория на двух датах, повторяемость, редкая категория, обе причины пустой выдачи и обязательное наличие обоих советов даты/бюджета. Каждый совет повторно отправляется в API: проверяются ровно одно изменённое поле, положительный результат и совпадение версии данных. Успех — JSON с status=PASS и измеренным request_ms. Это проверка API; браузерные проверки описаны ниже и в интеграционном отчёте.

Для отдельного порта:

```powershell
.\.venv\Scripts\python.exe scripts/smoke.py --base-url http://127.0.0.1:8002
```

Пример запроса к POST `/api/recommendations` (Content-Type: application/json):

```json
{
  "city": "Алматы",
  "event_date": "2026-10-15",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "duration_hours": null,
  "language": null
}
```

Параметры для выбора доступны через GET `/api/meta`. Из 10 ведущих Алматы на 15 октября проходят 6, выдаются до трёх; на 16 октября проходят 4. Точный top-3 определяется зафиксированным ранжированием. Для Алматы/Флорист/свадьба на 15 октября при том же бюджете подходят 2. Для Астаны с теми же остальными параметрами единственный флорист занят. Зарубежье/Ведущий даёт отсутствие категории; бюджет 1 ₸ для ведущих Алматы — существующую группу без подходящих.

## Как устроен подбор

CSV → нормализованный каталог в памяти → строгая валидация запроса → обязательные фильтры → стабильное ранжирование → до трёх карточек с фактами → при пустом результате проверенные предложения изменить одно условие. Подробнее — [архитектура и ранжирование](docs/ARCHITECTURE.md), [API-контракт](docs/API_CONTRACT.md).

Фильтры проверяют занятость, начальную цену, формат, запрошенный язык и часы. Пустой max_hours означает неприменимую длительность присутствия. При одинаковых параметрах порядок не зависит от случайности, текущего времени или исходного порядка строк. Цена «от» не гарантирует полную стоимость мероприятия. Доступность означает отсутствие даты в выданном календаре, не подтверждённую реальную бронь.

Три обычных результата: matched, no_category_in_city, no_matches. Ошибка ввода — HTTP 422, недоступность каталога/сервиса — 503. Ни пустая выдача, ни сбой не подменяются фиктивными карточками.

## Данные, настройки и ограничения

Исходный `data/contractors.csv` сохранён побайтово; [происхождение и SHA-256](data/README.md). Покрытие календаря 23.09.2026–31.12.2026; за пределами окна запрос отклоняется, потому что занятость неизвестна. Изменение CSV требует перезапуска и меняет dataset_version.

Обязательных переменных окружения нет; `.env` и ключи не нужны. Параметры запуска — `--port` и `--host`. Никакие сведения запроса не отправляются внешней модели или базе данных. Дополнительные синтетические профили командой пока не добавлены. Исходные записи не редактируются.

Деплой в интернете пока не выполнен. Основной способ проверки — локальный запуск. Фактические проверки общей версии фиксируются в [интеграционных отчётах](docs/integration/). Регистрация, бронирование, оплата и уведомления подрядчика вне объёма кейса.

## Дальнейшие улучшения проекта

Это идеи для следующих версий. Они ещё не реализованы и не входят в обещания текущего демо. Поиск в списках, календарь, автоподбор, справка о ценах, интерфейс на RU/KK/EN и работа на телефоне уже есть.

### Сначала — удобство и понятные объяснения

- **Более точные объяснения.** Находить больше конкретных услуг и особенностей в исходных описаниях, особенно у фотографов и видеографов. Сравнивать новые тексты с исходными данными и давать людям читать их без имён подрядчиков. Когда сведений мало, прямо сообщать об этом.
- **Казахский и английский для содержания карточек.** Перевести объяснения и описания, сохранив оригинал и проверив факты. Сейчас переводится интерфейс, а исходные тексты остаются русскими с явной подписью.
- **Сохранение и сравнение вариантов.** Сохранять выбранные карточки на устройстве, сравнивать цену «от», языки и длительность, возвращаться к прошлому запросу. Добавить ссылку с параметрами поиска, чтобы поделиться теми же условиями.
- **Доработка дизайна по проверке с людьми.** Проверять понятность формы, цены и причин пустой выдачи; улучшать чтение с телефона, управление клавиатурой и чтение экранным диктором. Текущая адаптация уже есть; дальнейшие изменения должны сохранять все рабочие состояния и порядок результатов.

### Затем — более полные и свежие данные

- **Обновление каталога без потери запроса.** Упростить загрузку новых цен и занятости, показывать дату обновления, при смене набора данных сохранять допустимые значения формы. Проверять данные перед публикацией; неизвестную доступность явно отличать от свободной даты.
- **Понятный состав цены.** Добавить подтверждённые пакеты услуг: что входит в цену, сколько стоит расширенный состав, какие доплаты возможны. До получения этих сведений цена «от» остаётся только начальной ценой.
- **Настоящие портфолио и контакты.** Подключить фотографии, примеры работ и способы связи после получения достоверных сведений и разрешения на публикацию. Рейтинги и отзывы добавлять только с проверяемым происхождением. В текущем анонимизированном наборе нельзя придумывать эти сведения.

### После проверки пользы — развитие сервиса

- **Демо по общей ссылке.** Разместить приложение в интернете, проверить доступ с другого устройства, настроить защищённое соединение, наблюдение за ошибками и восстановление после сбоя. Сейчас подтверждён локальный запуск; публичной ссылки пока нет.
- **Запрос обычными словами.** Исследовать ввод вроде «нужен фотограф на свадьбу в Алматы». Сначала показывать пользователю распознанные условия; сохранять строгую проверку даты, цены, языка и длительности. Если подключать языковую модель, отдельно измерить пользу, время ответа, стоимость и точность, предусмотреть работу без неё. Текущий подбор не вызывает внешнюю модель; изменение ранжирования B09 в пакет хакатона не входит.
- **Проверка на большем каталоге.** Измерить скорость и качество на более разнообразных реальных данных, следить за повторяемостью результата. Для сопровождения добавить простой способ увидеть версию приложения и данных; сейчас версия данных уже передаётся API, а версия приложения проверяется через Git.

Бронирование, платежи и личные кабинеты возможны как отдельный будущий этап после проверки спроса и получения реальных данных. Для текущего задания они не требуются. Порядок реализации определяем по пользе для пользователей и результатам проверки; ни один пункт не должен подменять отсутствующие факты выдуманными.
